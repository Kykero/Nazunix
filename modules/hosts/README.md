# modules/hosts/

Per-machine implementation. Which machines exist is declared only in
[`../hosts.nix`](../hosts.nix); this folder holds what each of them is made of.

## Registry vs implementation

- `modules/hosts.nix` lists the den hosts and their users, nothing else.
- `modules/hosts/<machine>/` defines the aspects those hosts include: the
  machine's hardware aspect and its machine-only settings.

## Two entities per machine

Each machine is declared twice in `hosts.nix`:

- `<machine>`: the `full` profile (default), the real environment.
- `<machine>-base`: the same machine (`hostName = "<machine>"`) with
  `profile = "base"`, the install gateway. It is installed first so the
  binary caches are written to `/etc/nix/nix.conf` before the full profile
  is pulled ([docs/install.md](../../docs/install.md)).

Both include one shared hardware aspect, `<machine>-hw`, so they boot on the
same disk layout and kernel modules.

## Files in a machine folder

| File | Role |
|---|---|
| `<machine>.nix` | defines `<machine>-hw` (boot, zram, dual boot, power) and what `<machine>` and `<machine>-base` include; the full entity adds extras such as `gaming` |
| `disko.nix` | disk layout, written into `<machine>-hw`: GPT, 1G ESP, btrfs with `@root @home @nix @log` |
| `hardware.nix` | generated by `den-bootstrap` from `nixos-generate-config --no-filesystems`: kernel modules and microcode only |
| `display.nix`, `mouse.nix` | niri output and pointer settings, set on `<machine>` only through `provides.to-users.homeManager`; the `-base` entity has no niri |

Current machines: `dazai` (laptop: zram, laptop power, Steam only) and
`yamori` (desktop and builder: full `gaming` bundle, no zram).

## Adding a machine

Run `den-bootstrap` and pick "new host"
([docs/install.md](../../docs/install.md)). It renders the templates in
[`templates/host/`](../../templates/host/):

- `host.nix.in` -> `modules/hosts/<host>/<host>.nix`, with zram kept when the
  machine has less than 16 GiB of RAM
- `disko.nix.in` -> `modules/hosts/<host>/disko.nix`, with the chosen disk
- `hosts-entry.nix.in` -> `<host>` and `<host>-base`, spliced into
  `hosts.nix` above the `den-bootstrap inserts new hosts above this line`
  marker

and generates `hardware.nix`. Commit and push after the first boot.

No hardware identifiers go in these files: disks are referenced by
`/dev/...` path, never `by-id`, and no serials or MACs.
